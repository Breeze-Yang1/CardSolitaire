# 纸牌程序需求一临时技术决策记录

> 本文件记录当前阶段已确认的实现口径。最终版本可能会根据后续需求、资源文件、联调结果和代码实现情况调整。

## 1. 当前玩法边界

- 当前实现目标为纸牌消除类 Demo，参考需求文档中的主牌区、手牌区、底牌和回退功能。
- 主牌区牌阵不写死在代码中，采用配置文件读取。
- 手牌区包含未翻开的手牌堆、当前底牌和回退按钮。
- 当前版本不加入 Joker 或 Wild 牌逻辑。
- `A` 与 `K` 不视为相邻牌，不能互相消除。

## 2. 匹配规则

- 桌面牌与当前底牌按点数相邻关系匹配。
- 花色不参与匹配判断。
- 点数关系采用普通线性顺序：`A, 2, 3, ..., 10, J, Q, K`。
- 两张牌的点数差值为 `1` 时可匹配。
- `A` 与 `K` 的点数差值不做循环处理，因此不可匹配。

## 3. 桌面牌可操作判定

- 每张桌面牌在配置中维护自身被哪些牌覆盖。
- 牌被移除后，系统重新计算其下层牌是否仍被其他未移除牌覆盖。
- 当一张桌面牌没有未移除的覆盖牌时，才允许玩家点击并参与匹配。
- 消除后是否翻开下层牌，取决于下层牌是否还存在其他覆盖关系。

## 4. 回退规则

- 当前版本已改为支持多步回退。
- 每次有效操作前保存一次完整快照，并压入回退栈。
- 每点击一次回退按钮，恢复最近一次快照并从栈中移除。
- 当前阶段不做重做功能。
- 当前需要支持两类回退：
  - 翻手牌后恢复翻牌前的手牌堆和底牌。
  - 消除桌面牌后恢复被消除牌、底牌和覆盖关系状态。

## 5. 代码结构决策

- 数据、规则、配置读取和视图分离。
- `GameModel` 管理当前牌局状态、匹配判断、消除、翻手牌和回退。
- `LevelConfig` 负责从 JSON 配置读取牌阵、初始底牌和手牌堆。
- `CardSprite` 只负责单张牌的显示，不直接写业务规则。
- `GameScene` 负责加载配置、创建界面、响应点击并同步模型状态。

## 6. 资源与显示

- 已从需求文档附带的 `res.zip` 中提取牌面基础图、点数字体和花色图。
- 当前资源包没有单独的牌背图，临时方案为复用基础牌面并通过颜色区分背面。
- 设计分辨率暂按需求文档中的 `1080 * 2080` 处理。
- 主牌区高度按 `1500` 处理，手牌区高度按 `580` 处理。

## 7. 环境状态

- 当前目录初始未包含 Cocos2d-x 工程，已补充可接入 Cocos2d-x 3.17 的源码、资源、配置和构建骨架。
- 已安装并确认可用的工具：
  - CMake：`C:\Program Files\CMake\bin\cmake.exe`
  - Visual Studio Build Tools 2022：`C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools`
  - MSVC：`cl.exe` 已可通过 `vcvars64.bat` 初始化后调用
  - Git：`git version 2.54.0.windows.1`
- Cocos2d-x 3.17.2 已通过 Gitee 镜像拉取到 `third_party/cocos2d-x-3.17.2`。
- `external` 第三方依赖已通过 Gitee 上的 `cocos2d-x-3rd-party-libs-bin` 镜像补齐。
- 当前项目已通过 `Visual Studio 17 2022 + Win32 + Debug` 构建，生成产物为 `build/bin/Debug/CardSolitaire.exe`。
- 64 位构建暂不作为当前验证目标。Cocos2d-x 3.17 的 Win32 EditBox 代码和预编译依赖更贴近 32 位 Windows 工程口径。
